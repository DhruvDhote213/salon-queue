The agent got one small thing wrong that made the whole app look broken. The frontend picks which backend to call using an API_URL line: use http://localhost:3000 when running locally, and the Render address when deployed. The agent only checked for localhost, but VS Code's Live Server opens pages on 127.0.0.1. So the page kept calling a placeholder Render address, and every button showed "Server unreachable".

I noticed because the backend was clearly fine: localhost:3000/api/state showed JSON in my browser, but the page still failed. That told me the problem was which address the page was calling, not the server. My first attempt to fix it was also wrong, because I wrote 127.0.0.1:5500 in the check. The browser's hostname never includes the port, so it never matched. I found this by comparing my line with the agent's and printing API_URL in the browser console. The fix was to compare against 127.0.0.1 alone.

I changed how I prompt. Instead of "it's not working", I now say where it happens, what I did, what I saw and what I expected, and ask the agent to explain the cause before changing code. I also added the local setup details to my docs: run the backend on port 3000, and open the page through Live Server.
